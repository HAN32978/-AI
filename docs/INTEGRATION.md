# 与 Windows LangChain + RAG 客服项目的集成方案

## 已有基线

`upstream/` 保存 AI-CAD-Audit-System 上游代码。其流程覆盖 CAD/DXF 解析、规则检查和审查报告。当前未对用户的 Windows RAG 项目作任何代码假设，尚未声称集成完成。

## 建议的演示场景

1. 业务人员上传示例 DXF 或选择离线演示数据。
2. 审查引擎返回问题清单，包含专业、图元/位置、规则编号及审查结论。
3. RAG 服务检索已获授权的规范条文、项目管理制度与施工流程资料，返回原文出处和版本。
4. LangChain 编排将问题、检索证据和可追踪的审查依据组合成建议；无法确定时标明需要人工复核。
5. 前端呈现图纸证据、规范出处、审查建议和可导出的报告。

## 接口边界（待对照本地项目调整）

- 输入：`project_id`、`drawing_id`、`question`、可选审查问题对象。
- 检索输出：`text`、`source`、`version`、`page_or_clause`、`score`。
- 审查输出：`issue_id`、`discipline`、`location`、`rule_id`、`evidence`、`status`。
- 最终回答：结论、引用、适用范围和人工确认状态。

## 接入前需要的材料

- Windows RAG 项目代码或仓库地址、启动方式及依赖清单。
- 脱敏后的规范样例与 DXF 样例；确认允许在公开仓库使用。
- 当前向量库、embedding、LLM 接口和密钥配置方式（只需配置项名称，不要提供密钥值）。

## 验收目标

能在一套干净的 Windows 环境启动两个模块；用固定样例复现审查、检索、引用与报告；缺失规范证据时明确提示人工复核。随后再补充权限隔离、日志、评测和部署方案。
