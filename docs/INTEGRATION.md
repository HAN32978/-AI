# 项目一、监理智查与图纸审查集成说明

## 来源与职责

- `rag_app/` 取自此前本地修改的“监理智查”项目。该项目沿用项目一的 RAG 模块，并改过配置、前端、模型接入等。仅复制源代码和无密钥配置样例，排除了 `.env`、模型、上传资料、向量库和日志。
- `upstream/` 与 `cad-spatial-analysis/` 是此仓库原有的上游代码；其许可证仍在各自目录。
- 本次新增审图问题导出脚本、RAG 证据匹配接口、Streamlit 工作流页面和源码面试文档。

## 数据契约

上游 `ProblemPool.to_json()` 导出 `{ "issues": [...] }`，每条问题至少需有 `description`；可选 `issue_id`、`professional`、`drawing_name`、`location`、`severity`、`standard_code`、`standard_clause`。最多一次提交 50 条，`top_k` 为 1–10。

```text
CAD 审查 / 问题池 JSON
  → 校验审查问题字段
  → 由专业、检查点、问题描述、待核查规范编号组合检索查询
  → Chroma/FAISS 召回工程资料片段
  → 展示来源文件、页码与原文
  → 缺依据 / A级风险 / 一般问题分别标记复核状态
  → 专业人员核对图纸与现行规范后处理
```

接口只返回“候选依据”。向量召回的内容可能不相关或版本过期；CAD 模块给出的规范编号也是待核查字段，不能代替正式审查结论。`project_name` 当前仅作为报告标签，未实现项目级索引隔离或过滤。

## 启动顺序

1. 配置并启动 RAG API 与前端；上传经授权的工程资料，等待后台向量入库。
2. 用上游审图模块导出问题池 JSON，或先用 `integration/examples/demo_issues.json` 演示。
3. 在“图纸审查工作流”页上传 JSON，查看候选来源和待复核状态，下载结果 JSON。
