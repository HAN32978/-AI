# 启动与问答故障修复

日期：2026-10-07。置信度：高（日志、代码、HTTP 回归和浏览器观察）；工程回答准确率：未知。

## 实际发现的问题

| 现象 | 证据与原因 | 修复 |
|---|---|---|
| `python run_api.py` 提示文件不存在 | 终端在根目录，脚本位于 `rag_app/` | 先 `cd rag_app` |
| 回答区文字接近不可见 | 自定义浅色背景混用了深色主题文字 | 添加项目浅色主题和聊天区域明确颜色；浏览器确认文字可读 |
| 问答失败，但 HTTP 仍为 200 | Ollama `/api/tags` 返回空模型列表；日志提示默认模型 404；原链将异常转换为普通答案 | 安装默认本地模型；调用前检查指定模型；错误返回 503；前端显示操作步骤 |
| 上传 Excel 后查询不到内容 | 加载日志显示 HTTP 403，后台未入库 | 用 pandas/openpyxl/xlrd 直接读取工作表；Markdown 直接读文本，避免不必要的 NLP 下载 |
| 工程 Excel 标题被当成列名 | 首行合并单元格是标题，第二行才是表头 | 从首个多单元格非空行读取列名；保留前面的标题；只为数据行建立文档 |
| Excel 引用显示“第 1 页” | 原链给没有页码的文档填了默认页码 | 引用返回真实工作表和行号；没有页码时不编造页码 |

## 面试可以如何讲

> 这次集成最初通过了上传和检索测试，但真实问答测试发现：SDK 客户端可以初始化，实际模型却不存在；后台文件上传成功也不代表解析成功。我根据运行日志分别定位了模型 404、Excel 解析 403和界面主题混用，增加了模型就绪检查、明确的失败状态与表格行号引用，再用合成 Excel 完成真实模型回归。测试能证明这个用例跑通，不能据此宣称工程准确率或生产可用性。
